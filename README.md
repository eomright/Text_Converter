# 한국어 받아쓰기 (Korean STT)

브라우저에서 녹음하거나 파일을 올리면 **내 PC에서** 한국어 텍스트로 변환합니다.
외부 API를 일절 호출하지 않으므로 **비용 $0**, 음성이 외부로 나가지 않습니다.

설계 근거와 파라미터 선택 이유는 [DESIGN.md](DESIGN.md) 참고.

---

## 실행

```
start.bat
```

더블클릭하면 서버가 뜨고 4초 뒤 브라우저가 자동으로 열립니다.
직접 열려면 → **http://127.0.0.1:8000**

끄려면 터미널 창에서 `Ctrl + C`.

### 터미널에서 직접 실행하고 싶다면

```powershell
cd "C:\Users\jung3\OneDrive\문서\claude_workspace1\korean-stt"
& "$env:USERPROFILE\korean-stt-runtime\.venv\Scripts\python.exe" -m uvicorn server.main:app --port 8000
```

> 서버가 뜬 직후 20~30초 동안 모델을 메모리에 올립니다.
> 우상단 배지가 **"준비됨"** 으로 바뀌면 변환이 가능합니다. 그 전에도 업로드는 받아두고 순서대로 처리합니다.

## 사용법

### 두 가지 모드

화면 위쪽 토글로 고릅니다.

**⚡ 실시간** (기본값) — 말하는 동안 문장이 회색 기울임으로 하나씩 올라오고, 정지를 누르면
전체를 large-v3-turbo가 다시 돌려 **정확한 최종본으로 교체**합니다. 초안과 최종본을 둘 다 가져갑니다.

```
[말하는 중]  00:03  안녕하세요 오늘 발표를 맡은      ← small 초안 (회색)
[정지]       ▓▓▓ 정밀 변환 중…
[완료]       00:00  안녕하세요. 오늘 발표를 맡은 엄정석입니다.   ← 교체됨
```

**◎ 정확도 우선** — 실시간 초안 없이 정지 후 한 번만 변환합니다. CPU를 덜 씁니다.

> 실시간 모드에서 **문장을 말하고 4~5초쯤 뒤에** 초안이 뜹니다. 즉시 뜨지 않는 게 정상입니다.
> 충전기를 꽂으면 2~3초로 줄어듭니다 (아래 성능 항목 참고).

### 기능별 조작

| 하고 싶은 것 | 방법 |
|---|---|
| 녹음해서 변환 | 빨간 버튼 클릭 → 말하기 → 다시 클릭 (자동으로 변환 시작) |
| 파일 변환 | 오디오 파일을 페이지에 드래그 (mp3 · m4a · wav · webm · mp4) |
| 특정 구간 듣기 | 결과의 `[00:12]` 시간 클릭, 또는 파형 클릭 |
| 재생/정지 | 스페이스바 |
| 오타 수정 | 결과 텍스트를 클릭해서 고치면 **자동 저장**되고 내보내기에도 반영됩니다 |
| 꼼꼼히 교정 | 결과 위 **✎ 교정 모드** (아래 설명) |
| 저장 | `txt` / `srt`(자막) / `md` 버튼 |
| 지난 기록 | 맨 아래 "최근 기록"에서 클릭 |

### ✎ 교정 모드 — 들으면서 한 줄씩 고치기

변환이 끝난 결과에서 **✎ 교정 모드**를 누르면 전체 화면으로 바뀝니다.
줄을 고르면 **그 구간만 재생하고 끝에서 멈춰서**, 손을 키보드에서 떼지 않고 진행할 수 있습니다.

| 키 | 동작 |
|---|---|
| `Tab` / `Shift+Tab` | 다음 줄 / 이전 줄로 가면서 재생 |
| `Ctrl+Space` | 지금 줄 다시 듣기 |
| 그냥 타이핑 | 지금 줄 수정 |
| `Enter` | 확인(✓) 표시하고 다음 줄로 |
| `Esc` | 재생 정지 |

- **재생 속도**는 0.7~1.0배로 조절됩니다 (기본 0.8배)
- 고친 내용과 ✓ 표시는 **자동 저장**됩니다. 창을 닫았다가 다시 열면 확인 안 한 첫 줄부터 이어집니다
- ⚠ 는 틀렸을 가능성이 높은 줄입니다. **⚠ 안 끝난 줄만**을 켜면 그 줄만 모아 볼 수 있습니다

**모델 비교 분석** — 버튼을 누르면 다른 큰 모델(turbo ↔ large-v3)로 한 번 더 변환해서,
**두 모델이 다르게 들은 줄에 ⚠** 를 붙이고 다른 모델의 결과를 줄 아래에 보여줍니다.
녹음 길이의 1~3배 정도 걸립니다. 두 모델이 **똑같이 틀린** 줄은 못 잡으니, ⚠ 없는 줄도 들어보는 게 좋습니다.

**정답으로 저장** — 교정이 끝나면 오디오와 받아쓰기를 같은 이름으로 평가 폴더에 저장합니다.
그대로 `scripts/benchmark.py` 로 정확도를 잴 수 있습니다 (아래 "정확도 측정하기").

### 인식률을 올리고 싶으면 — 용어집을 꼭 쓰세요

**설정 · 용어집** 패널의 첫 번째 칸에 이런 식으로 적어둡니다.

```
연구실 세미나 녹음입니다. 참석자: 엄정석, 김교수님.
용어: HCLT, DPO, 아첨성, 파인튜닝, 선호도 최적화, 벤치마크.
```

이 문장이 모델에 문맥으로 주입되어(`initial_prompt`) **고유명사와 전문용어 인식률이 눈에 띄게 올라갑니다.**
이게 이 앱에서 정확도를 올리는 가장 효과적인 방법입니다.

그래도 계속 똑같이 틀리는 단어가 있으면 **치환 사전**에 `잘못 나오는 말 → 올바른 표기`를 등록하세요.

## 🏫 강의 녹음 — 교수님 목소리가 작고 멀 때

녹음 버튼 위의 **녹음 환경**을 `🏫 강의실` 로 바꾸세요. 바뀌는 것:

| | 🎙 가까이 | 🏫 강의실 |
|---|---|---|
| 정밀 변환 모델 | large-v3-turbo | **large-v3** (더 정확, 약 2배 느림) |
| 실시간 초안 | 그대로 | 작은 소리를 **자동 증폭**한 뒤 인식 (단, 초안은 매우 부정확) |
| 브라우저 잡음 억제 | 켬 | **끔** (멀리 있는 목소리를 잡음으로 지우지 않게) |

파일을 올릴 때도 이 설정이 적용됩니다. 휴대폰으로 녹음한 강의 파일도 `강의실` 로 두고 올리세요.

> **강의실에서는 `◎ 정확도 우선` 모드를 권합니다.** 뒷자리 녹음으로 실시간 모드를 테스트해보니
> 초안(small)은 오류율 **55%** 로 거의 읽을 수 없었고, 멈춘 뒤 large-v3 최종본은 **13.5%** 였습니다.
> 초안은 "녹음이 되고 있다"는 확인용 정도이고, 녹음 중 CPU를 써서 노트북 팬 소리만 늘립니다.

### 왜 "증폭"이 아니라 "큰 모델"인가

직접 재봤습니다. 뒷자리에서 녹음한 것처럼 만든 음성(작고, 울리고, 에어컨 소리)에서:

| 방법 | 오류율 |
|---|---|
| 처리 안 함 | 31.3% |
| **지금 방식 (음량 정규화)** | **21.6%** |
| 말소리 구간 추가 증폭 | 25.5% ← 나빠짐 |
| 신경망 잡음 제거 | 49.4% ← 크게 나빠짐 |
| **음량 정규화 + large-v3** | **13.5%** |
| **+ 용어집에 수업 용어 적기** | **11.0%** (정답에 나오는 용어를 적은 경우라 다소 낙관적) |

용어집은 **"강의 주제입니다" 같은 문장은 효과가 없고**, 슬라이드에 나오는 **용어를 쉼표로 나열**해야 효과가 있었습니다.
```
용어: 대규모 언어 모델, 미세 조정, 선호도 최적화, 편향, 성능 지표
```

음량을 맞추는 건 이미 하고 있고, 거기서 **더 키우거나 잡음을 지우면 오히려 나빠집니다.**
틀린 걸 보면 소리를 못 들은 게 아니라 **들린 걸 잘못 알아듣는** 거라서, 문맥으로 추측하는 힘이 센 큰 모델이 효과가 있었습니다.

### 가장 효과가 큰 건 녹음 위치

같은 조건에서 **앞자리 오류율 1.3%, 뒷자리 21.6%** 입니다. 어떤 처리보다 이 차이가 큽니다.
마이크에 안 들어간 소리는 소프트웨어로 되살릴 수 없습니다.

- **휴대폰을 교탁 쪽에 두고 녹음 → 수업 끝나고 파일 업로드** 가 가장 확실합니다
- 노트북으로 녹음한다면 **앞자리**, 그리고 모드는 `◎ 정확도 우선` 추천 —
  실시간 모드는 녹음 중 CPU를 써서 **노트북 팬 소리가 마이크에 같이 들어갈 수 있습니다**
- 에어컨·프로젝터 바로 옆자리는 피하기

### 걸리는 시간 (large-v3)

| 강의 길이 | AC 전원 | 배터리 |
|---|---|---|
| 1분 | 약 45초 | 약 1분 30초 |
| 75분 수업 | **약 55분** | 약 1시간 50분 |

수업 끝나고 **충전기 꽂고** 돌려두는 걸 권합니다. 급하면 설정에서 `가까이` 로 바꿔 turbo로 돌리면 절반 시간에 끝납니다.

### 도중에 서버가 꺼져도 괜찮습니다

긴 강의는 변환에 1~2시간이 걸려서, 그 사이 검은 서버 창이 닫히거나 노트북이 꺼질 수 있습니다.
이제는 그래도 작업이 사라지지 않습니다.

| 언제 꺼졌나 | 남는 것 |
|---|---|
| **녹음 중** (서버 꺼짐, 탭 닫힘) | 그때까지의 **녹음 파일**과 **실시간 초안** |
| **정밀 변환 중** | 녹음 파일, 초안, 그리고 **변환이 끝난 부분까지** (몇 문장마다 저장) |

서버를 다시 켜면 그 기록이 **최근 기록**에 `중단됨 35%` 처럼 표시됩니다.
기록을 열고 **이어서 변환**을 누르면 끊긴 지점부터 이어서 합니다. 앞부분을 다시 하지 않습니다.

서버를 켤 때 자동으로 이어서 하게 하려면 환경변수 `KSTT_AUTO_RESUME=1` 을 주고 켜세요 (기본은 꺼짐 — 켜자마자 긴 작업이 CPU를 차지하지 않도록).

> 정확도 우선 모드로 **녹음하는 중에** 탭을 닫으면 녹음이 사라집니다 (녹음이 끝날 때까지 브라우저에만 있기 때문).
> 녹음 중 탭을 닫으려 하면 브라우저가 한 번 물어봅니다. 긴 강의는 **실시간 모드**가 안전합니다.

## 실측 성능 (이 PC: Core Ultra 7 155H, GPU 없음)

Windows TTS로 만든 한국어 샘플 기준. 실제 사람 목소리는 이보다 조금 어렵습니다.

| 항목 | 측정값 |
|---|---|
| 정밀 모델 | large-v3-turbo (int8, CPU) — CER **0.6~3.9%**, 약 1.8x 실시간 |
| 실시간 초안 | small (int8, CPU) — CER **1.9%**, 문장 끝나고 2~5초 뒤 표시 |
| 모델 로드 | 최초 20~40초 (두 모델 모두 메모리 상주) |
| 메모리 | 약 3GB |

### ⚡ 충전기를 꽂으세요 — 속도가 2배 차이납니다

| 전원 | CPU 클럭 | 체감 |
|---|---|---|
| AC 전원 | ~2900MHz | 초안 지연 ~2.5초, 정밀 변환 1.8x |
| 배터리 | **1400MHz (37%)** | 초안 지연 ~4.6초, 정밀 변환 0.9x |

이 노트북(Core Ultra 7 155H)은 배터리 모드에서 CPU를 1400MHz로 제한합니다.
CPU 추론이라 클럭에 그대로 비례해서, **꽂기만 해도 거의 2배 빨라집니다.**
느리다고 느껴지면 제일 먼저 확인할 것.

10분짜리 회의 녹음이면 대략 6~7분 걸린다고 보면 됩니다.

> **초반 20초 정도는 화면이 비어 있는 게 정상입니다.**
> 모델이 30초 단위로 묶어서 처리하기 때문에 첫 문장이 나오기까지 20~25초 걸립니다.
> 그 뒤로는 10초마다 문장이 묶음으로 쌓이므로 끝까지 기다릴 필요는 없습니다.
> 진행률 바가 움직이고 있으면 정상 동작 중입니다.

**더 빠르게** 하고 싶으면 설정에서 모델을 `small`이나 `medium`으로 바꾸세요 (정확도는 떨어짐).

## 정확도 측정하기 (선택)

주관적인 느낌 대신 숫자로 모델을 고르고 싶을 때.

1. `data\eval\` 에 **오디오와 같은 이름의 정답 텍스트**를 둡니다.
   **교정 모드의 "정답으로 저장"** 을 누르면 자동으로 이렇게 저장됩니다.
   ```
   data\eval\회의.m4a
   data\eval\회의.txt      ← 직접 받아쓴 정답
   ```
   정답은 **읽지 말고 들으면서** 고치고, 추임새·숫자·영어 용어 표기 규칙을 통일하세요.
   표기가 섞이면 모델이 맞게 들었어도 틀린 걸로 셉니다.
2. 실행:
   ```powershell
   cd "C:\Users\jung3\OneDrive\문서\claude_workspace1\korean-stt"
   & "$env:USERPROFILE\korean-stt-runtime\.venv\Scripts\python.exe" -X utf8 -m scripts.benchmark
   ```
3. 모델별 CER(문자 오류율)과 속도가 표로 나옵니다.

용어집 효과를 재보고 싶으면 `--prompt "용어: HCLT, DPO"` 를 붙여서 비교하세요.

## 문제가 생기면

| 증상 | 원인 / 해결 |
|---|---|
| 마이크가 안 잡힌다 | 브라우저 주소창 왼쪽 자물쇠 → 마이크 허용. `localhost`는 http여도 허용됩니다 |
| 같은 말이 계속 반복된다 | 환각 현상. `server/config.py`의 `condition_on_previous_text`가 `False`인지 확인 |
| 무음인데 이상한 자막이 나온다 | `vad_filter`가 `True`인지 확인. `no_speech_threshold`를 0.7로 올려보세요 |
| 너무 느리다 | 설정에서 `small` 모델로 전환. 다른 무거운 프로그램을 닫으면 체감이 달라집니다 |
| 전문용어를 계속 틀린다 | 용어집에 등록 (위 참고) |
| `ffmpeg` 오류 | `ffmpeg -version` 이 되는지 확인. PATH에 없으면 전처리가 실패합니다 |
| 포트 8000 충돌 | `--port 8001` 로 바꿔서 실행 |
| 실시간 초안이 안 뜬다 | 우상단 배지가 "준비됨 (… + small)" 인지 확인. small 로딩 전이면 초안이 안 나옵니다 |
| 초안이 문장 중간에 끊긴다 | `server/config.py` 의 `LIVE_SILENCE_MS` 를 500 → 700 으로 올리세요 (대신 지연 증가) |
| 초안 지연이 너무 길다 | 충전기 연결. 그래도 길면 `LIVE_SILENCE_MS` 를 400으로 내리세요 |
| 기록에 텍스트가 없고 `중단됨` 으로 뜬다 | 변환 도중 서버가 꺼진 것. 기록을 열고 **이어서 변환** (위 "도중에 서버가 꺼져도 괜찮습니다") |

### 다시 설치해야 할 때

& "$env:USERPROFILE\korean-stt-runtime\.venv\Scripts\python.exe" -m pip install -r server\requirements.txt

  audio.py        ffmpeg 전처리 (16kHz 모노 + 음량 정규화)
  postprocess.py  반복 환각 제거 + 용어집 치환 + txt/srt/md 변환
  db.py           SQLite
web/index.html    프론트엔드 전체 (외부 CDN 없음 — 오프라인 동작)
scripts/benchmark.py          모델별 CER 측정
scripts/preprocess_bench.py   전처리 방식별 CER 비교 (내 강의 녹음으로도 가능)
